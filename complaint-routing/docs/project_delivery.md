## 5. المشاكل يلي واجهناها، وكيف انحلّت

### البيئة

| المشكلة | الحل |
|---|---|
| الكرت مو ظاهر لـ TensorFlow على WSL2 | السجل المفصّل بيّن إنو `libcusolver.so.11` بس ما انفتح. إضافة مجلده لـ `LD_LIBRARY_PATH` بملف `activate` |
| الكرت بيختفي بالدفاتر | Kernel خاص فيه نفس المتغيّر |
| VS Code بيفتح ملفات Ubuntu | فتح مسار `/mnt/c/...` من نافذة WSL |
| انقطاع VS Code عن WSL أثناء تدريب كبير | `Reconnect` أو `wsl --shutdown` |
| دورة أخدت ساعة | الجهاز نام، إعدادات الطاقة |

### الكود

| المشكلة | الحل |
|---|---|
| تجارب جديدة كانت رح تكتب فوق القديمة | اسم تشغيل تلقائي من الإعدادات |
| الحشو كان ممكن يخرّب المتوسط والانتباه | Masking، مع اختبار: قصيرة ومحشية لازم يطلعوا نفس الملخّص |
| حفظ نموذج فيه طبقة مخصّصة | `register_keras_serializable` |
| الأزواج بتضاعف طول الشكوى | `max_len` من 420 لـ 840 |
| `NameError` و `KeyError` بعد تعديلات | ترتيب `main`، وتحديث كل مكان بينادي الدالّة المعدّلة |
| السكريبت ما لقى النموذج من الدفتر | المسار من مكان ملف الإعدادات، مو من مكان التشغيل |
| أول قياس وقت 109 ms | تسخين، 500 شكوى، حكم على p95، وبناء قائمة الكلمات مرّة وحدة |

### المنهجية

| المشكلة | الحل |
|---|---|
| تفسير النتيجة بعد ما تبيّن | جدول «كل نتيجة شو بتعني» قبل التشغيل |
| فرق صغير انقرأ كتحسّن | مقارنته بتذبذب البذور |
| مقارنة الفجوة بآخر دورة | مقارنتها بنفس الدورة |
| الحكم على أداة بجرعة ضعيفة | رفع الجرعة قبل الحكم |
| الإحساس إنو التضمين هو المشكلة | تجربة رخيصة بتقسم الاحتمالات حسمت |
| مقارنة الشبكة بخط أساس بأوزان مختلفة | إعادة الشبكة بنفس الأوزان |
| تجارب Dropout وأول تجربة أزواج انشغّلت بالانتباه بدل المتوسط | انكشف من أسماء التقارير. الدرس: سطر `run:` جزء من الناتج يلي بينقرا ببداية كل تشغيل، وأي تجربة بلاه ما بتنعتمد |
| خط الأساس كان بيشوف أزواج والشبكة لأ، وما انتبهنا من الأول | مراجعة إعدادات خط الأساس قبل أي مقارنة |

## 6. دروس المشروع

1. افهم المشكلة قبل الحل: عَرَض، تشخيص بفرضيات، أثر.
2. كل أداة جواب على مشكلة: شو بتحلّ؟ هل مشكلتها موجودة؟ شو تكلفتها؟
3. قرّر شو بتعني كل نتيجة قبل ما تشوفها.
4. ابدأ بالتجربة يلي بتقسم الاحتمالات أكبر قسمة بأقل تكلفة.
5. أحياناً غيّر الطرف التاني: نزّل خط الأساس لظروف الشبكة بدل العكس.
6. تذبذب البذور هو الميزان. فرق أصغر منه مو تحسّن.
7. الفجوة أداة تشخيص مو هدف. ممكن تصغر لأن التدريب نزل.
8. قبل ما تحكم إنو أداة فشلت، تأكّد إنك استعملتها بجرعة كافية.
9. المقارنة العادلة: نفس الميزات والأوزان، والفرق الوحيد هو يلي عم تختبره.
10. قبل ما تقارن مع خط الأساس، اعرف بالضبط شو بيشوف.
11. الحل البسيط ممكن يكون الصح، وإثباته بالأرقام نتيجة ناجحة.
12. الاختبار مرّة وحدة. كل شي بيأثّر على قرار على التحقّق، حتى تحليل الأغلاط.
13. القيود بتتقاس على توزيع بعد التسخين، مو على استدعاء واحد.
14. تحليل الأغلاط بيكشف السقف: إذا أغلب الأغلاط التباس بالتسمية، نموذج أقوى ما رح يفيد كتير.
15. للعميل: أرقام، حدود، خيارات. مو تبرير ولا لوم للبيانات.

## 7. نقاط مفتوحة

- أسئلة للعميل: العتبة، إلزامية التبرير، رفع القيود، دمج أو إعادة تعريف الأقسام المتداخلة.
- تحليل الأغلاط على عيّنة أكبر، مع خبير مالي.
- `config.yaml` لسا فيه إعدادات آخر شبكة (`mean`، أزواج، 50 ألف، أس 0.5). ما بتأثّر على النموذج المسلَّم، بس لازم تنذكر إذا حدا رجع للتجارب.
- `requirements.txt` فيه TensorFlow للتجارب. الاستدلال بيحتاج `scikit-learn`، `joblib`، `numpy`، `pandas`، `pyyaml` بس.
