## 3. أول عقبة: لا يوجد عمود هدف

الداتا لا تحتوي عمود هدف جاهز، بخلاف المشاريع السابقة. الهدف موجود ضمنياً في بنية الملف ويجب استخراجه.

المنطق: آخر دورة مسجّلة لكل محرك في الـ train هي لحظة عطله. إذاً:

```python
max_cycle = train.groupby("unit")["cycle"].transform("max")
train["RUL"] = max_cycle - train["cycle"]
```

استُخدمت `transform("max")` لأنها تُرجع سلسلة بطول الداتا الأصلية — كل صف يأخذ أقصى دورة تخص محرّكه هو — بينما `groupby().max()` تُرجع قيمة واحدة لكل محرك وتتطلب دمجاً إضافياً.

### الوحدة المستقلة

الصف ليس وحدة مستقلة. الصفوف المتتالية لنفس المحرك مترابطة بشدة. الوحدة المستقلة هي **المحرك**.

هذا المبدأ يُطبَّق عند **التقسيم**، لا عند حساب الهدف.

## 9. هندسة الأعمدة

### أ. الانحراف عن خط الأساس

كل محرك يبدأ من قيم ابتدائية مختلفة. المهم ليس القيمة المطلقة بل مقدار ابتعاد المحرك عن حالته السليمة.

```python
base = df[df.cycle <= 20].groupby("unit")[FEATURES].mean()
for c in FEATURES:
    df[c + "_dev"] = df[c] - df["unit"].map(base[c])
```

**النتيجة: 19.39 → 16.09** (تحسّن 17%)

الانحراف يفصل عاملين كانت القراءة الخام تخلطهما: مقدار تدهور المحرك، ومقدار اختلافه الفردي عن غيره. المحرك 39 بدأ عند 1410 والمحرك 69 عند 1400 — عشر وحدات فرق بين محرّكين **كلاهما سليم**.

### ب. التنعيم والميل

مشكلتان بقيتا:

**الضجيج** — `s4_dev` تأرجح من -6.07 إلى +1.61 خلال ثلاث دورات، بينما إشارة التدهور عند RUL=110 كانت +3.03 فقط. ضجيج الدورة الواحدة أكبر من الإشارة المبكرة.

**غياب الاتجاه** — الانحراف يقول أين المحرك، لا إلى أين يتّجه. محركان بانحراف +3، أحدهما صاعد والآخر هابط، حالتان متعاكستان بنفس القيمة.

الحل: نافذة متحركة تعطي الاثنين معاً.
Rolling Window

المتوسط يعطي الموقع بلا ضجيج، والميل يعطي الاتجاه.

المبدأ مطابق لـ PD controller — القيمة الحالية ومعدل تغيّرها.

### خطأ منهجي وقع وصُحّح

الميل حُسب أولاً من القيم **الخام**، فورث الضجيج كاملاً:

```
+0.774 → +0.024 → -0.621 → +0.298 → -0.054
```

انقلاب في الإشارة كل دورة، بينما المحرك لم يتغيّر فيه شيء.

**الاشتقاق يكبّر الضجيج.** نفس المبدأ المعروف في الحد التفاضلي بالـ PID، حيث يوضع مرشّح قبله دائماً.
filtered derivative

التصحيح: التنعيم أولاً، ثم الاشتقاق من القيمة المنعّمة.

```python
for c in DEV:
    df[c + "_mean"] = g[c].rolling(win, min_periods=1).mean().values

g2 = df.groupby("unit")
for c in DEV:
    m = c + "_mean"
    df[c + "_slope"] = ((df[m] - g2[m].shift(win - 1))
                        / (win - 1)).fillna(0).values
```

النتيجة بعد التصحيح:

```
+0.465 → +0.410 → +0.235 → +0.212 → +0.130 → +0.087 → +0.023
```

نزول متدرج بلا انقلاب — قراءة قابلة للتفسير: تغيّر موجب يخفّ تدريجياً حتى الاستقرار، أي محرك سليم ثابت. صحيح فيزيائياً عند الدورة 22.

**النتيجة: 16.09 → 14.56**

طول النافذة المستخدم: 15 دورة.

### قيود تصميمية

النافذة تُحسب داخل كل محرك عبر `groupby`، وتنظر إلى الماضي فقط. الحساب على الداتا كاملة يجعل محركاً يأخذ قيماً من محرك آخر، والنظر إلى المستقبل تسريب مباشر.

### مسألة مؤجلة

أول 14 صفاً من كل محرك ميلها صفر بفعل `fillna(0)` — النافذة لم تكتمل بعد. هذه أصفار **كاذبة**: الصفر يعني "مستقر" وهو ادعاء عن حالة المحرك، بينما الحقيقة أن المعلومة غير متوفرة. الأثر ≈ 1,400 صف. لم تُعالَج.

**overfitting حقيقي**: الموديل يحفظ ضجيجاً، فيسوء الأداء على داتا جديدة، ويتحسّن عند التقييد.

**ما حدث هنا**: الموديل يحفظ التدريب، لكن الأداء على داتا جديدة لا يتأثر، والتقييد لا يحسّنه.

## 14. النشر

Deployment

### قيد أساسي

الموديل لا يعمل على قراءة واحدة. الأعمدة المهندسة تحتاج تاريخاً: خط الأساس من أول 20 دورة، والتنعيم والميل من آخر 15 دورة.

الدالة تأخذ **سجل المحرك**، لا لقطة.

```python
def predict_rul(engine_history, model=rf, cap=120):
    """
    تتنبأ بالعمر المتبقي لمحرك وتصنّف حالته.
    المدخل: DataFrame فيه cycle + الحساسات الـ 21، مرتباً زمنياً.
    """
    df = engine_history.copy()

    if len(df) < 20:
        raise ValueError(f"يلزم 20 دورة على الأقل، المتوفر {len(df)}")

    df = df.sort_values("cycle")
    df["unit"] = 1

    df = add_deviation(df)      # نفس دوال التدريب
    df = add_rolling(df)

    rul = float(model.predict(df.tail(1)[COLS_3])[0])
    rul = max(0.0, min(rul, cap))

    if rul <= 20:
        status = "حرج - صيانة فورية"
    elif rul <= 50:
        status = "تحذير - جدولة صيانة"
    elif rul < cap:
        status = "مراقبة"
    else:
        status = "سليم"

    return {"RUL": round(rul), "الحالة": status,
            "دورات مسجلة": len(engine_history)}
```

### قرارات التصميم

**استدعاء دوال التدريب نفسها** — كتابة معالجة منفصلة للنشر يجعل أي اختلاف بسيط بينهما يعطي نتائج خاطئة بصمت.
Training-Serving Skew

**التقييد بين 0 و 120** — الموديل قد يعطي رقماً سالباً أو أعلى من السقف، وكلاهما بلا معنى فيزيائي.

**التصنيف** — الرقم وحده لا يفيد مشغّل الصيانة. العتبات مبنية على نتائج تشريح الخطأ: تحت 20 دقة الموديل 5.85 دورة، فالإنذار موثوق هناك.

## 15. الدروس

**1. الهدف قد لا يكون عموداً.** استخراجه من بنية الملف كان أول خطوة، وطريقة تمثيله (السقف) كانت أهم قرار في المشروع كله.

**2. هندسة الأعمدة تفوّقت على تغيير الموديل.** الخطي بأعمدة مهندسة (14.56) تفوّق على الغابة بأعمدة خام (16.06). المعلومة المعطاة للموديل أهم من الموديل نفسه.

**3. نعّم قبل أن تشتق.** الاشتقاق يكبّر الضجيج. الميل المحسوب من قيم خام انقلبت إشارته كل دورة رغم استقرار المحرك.

**4. الفجوة بين التدريب والتحقق ليست دائماً إنذاراً.** اثنتا عشرة تركيبة أعطت نفس النتيجة ضمن 0.56 دورة. حين لا يحسّن التقييد الأداء، فالحفظ ليس ضاراً والقيد في مكان آخر.

**5. الرقم الواحد يخفي البنية.** 11.04 كمتوسط أخفى أداءً ممتازاً قرب العطل (5.85) وضعفاً في الوسط (16.75) وانحيازاً منهجياً في الاتجاه الخطر.

**6. المقياس يجب أن يعكس كلفة الخطأ الحقيقية.** RMSE يربّع الخطأ فيلغي إشارته، ويعامل التنبؤ المتفائل الخطر والمتحفظ الآمن بالتساوي.
